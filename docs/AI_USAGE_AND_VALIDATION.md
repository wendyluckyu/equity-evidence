# AI 使用与验证记录

最终确认日期：2026-10-03。记录区分开发辅助 AI 和产品运行时 AI；不将生成内容或测试通过等同于金融结论正确。

## 使用的 AI 与分工

| 环节 | 工具 | 实际用途 | 人工判断或程序约束 |
|---|---|---|---|
| 产品方案与开发 | Codex | 梳理题目、设计主链路、编写界面及服务端、生成测试与文档 | 用户确认目标体验、视觉方向、修改范围和最终版本 |
| 数据理解与口径核查 | Codex 辅助检查接口字段与公告 | 对齐财务期次、追溯字段与原文、识别口径错误 | 指标公式由程序执行；公告保留来源与页码；没有证据不补全 |
| 网站中的研究问答 | DeepSeek，默认 deepseek-flash | 根据当前问题、最近三个问题、公司类型和证据库，选择相关证据、安排研究重点及后续问题 | 不允许模型自行生成展示事实；输出只含受约束的证据 ID 与范围判断 |
| 测试与复查 | Codex + 自动化测试 | 检查确定性计算、异常数据、输出结构及页面流程 | 测试使用合成数据；真实接口验证仅作有限样本记录 |

## 产品运行时链路

1. 服务端调用扶摇获取结构化财务、估值和行情；公告来自已整理的深交所、巨潮资讯原文。
2. 程序按报告期对齐，计算同比、毛利率、现金流覆盖与行情回撤，生成包含来源、字段、单位和适用边界的证据条目。
3. 程序检查核心财务可用性、三项公告交叉核对及资料时效；部分异常会暂停 AI 解读，证据层保留未知或历史状态。
4. DeepSeek 读取问题与证据库，返回 scope、focusIds、summaryIds、counterpointId、questionIds。模型选择条目，程序呈现对应的固定解释。
5. 检查字段白名单、有效引用、摘要与重点对应、反证或未知项。结构错误最多纠正一次；失败明确报错。
6. 模型漏选反证时，程序可从已有负面、矛盾或未知证据中补充，并在界面注明系统补充，不冒充模型选择。

## 迭代中发现并修正的问题

| 问题 | 修正 | 验证方式 |
|---|---|---|
| 毛利率容易混用营业总成本 | 使用营业收入与营业成本 | 纯函数测试 |
| 现金流与归母净利润口径不一致 | 现金流覆盖分母使用合并净利润 | 合成数据测试 |
| 相邻累计报告期容易误作单季环比 | 按相同财年报告期进行同比 | 同期匹配测试 |
| 原文为千元、接口为元 | 明确原文金额乘 1,000；展示亿元另行换算 | 三项中报数字与公告交叉核对 |
| 原版自由文本仅验证引用编号，不能证明语义支持 | 最终版约束为证据条目选择，模型不能新增展示事实 | 伪造引用、额外文本字段、摘要与重点对应测试 |
| 简单禁用数字误伤合法复述 | 展示数字来自程序和公告条目，不禁止已核实数字本身 | 有效证据选择测试 |
| 模型漏选反证导致请求失败 | 有界重试及明确披露的系统补充 | 合成测试与一次缺失账龄问题复测 |
| 旧行情混入新日期无效价格，可被误判为新数据 | 时效与计算共用有效价格筛选、未来排除和日期去重 | 时效、证据未知状态与隔离 API 拒绝测试 |
| 非人民币原始金额被标为人民币 | 按源币种显示；缺失币种显示未知 | CNY、USD、HKD、EUR 和缺失币种测试 |
| 新用户不清楚从哪里开始、文案和层级生硬 | 独立首页、清晰栏目、研究问答和逐层展开的证据 | 用户反馈与本地浏览器验证 |

## 仍需明确的局限

受约束输出降低了模型自由编造事实的风险，但不是完备的语义验证：模型可能选择不够相关的条目或反证，摘要也可能重复依据。它不能自动阅读全部新公告、验证用户笔记或完成任意新问题的研究。

问题上下文只包含最近三个用户问题，不含完整回答、当前打开的证据和用户核查记录。公司解释与因果推断仍须核对原文；三项公告交叉检查也不意味着所有指标、同行、报告期均已独立核实。

产品不提供确定性涨跌预测、收益承诺、目标价或直接买卖建议。已知范围和未做事项见 README。
